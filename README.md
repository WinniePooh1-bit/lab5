## 1. Зорилго

Лекц 5-ын тест дизайны таван алхмыг бодит REST API дээр хэрэглэв: бие даан тестлэгдэх функцийг тодорхойлох, сонголтуудыг тогтоох, төлөөлөх утгууд сонгох, тестийн спецификаци гаргах, бодит тест кейс хэрэгжүүлэх. Бүртгэлийн API-г Node.js-ийн цэвэр http модулиар ажиллуулж, Postman Collection v2.1 форматаар тест зохион байгуулан Newman CLI-аар автоматаар гүйцэтгэв.

## 6. Бие даасан тест ба oracle

Тест бүр Postman Collection-ийн тусдаа folder дотор байна. Folder бүрийн эхэнд тухайн кейст шаардлагатай PUT хүсэлтүүдийг дарааллаар ажиллуулаад, хамгийн сүүлд POST /registrations хүсэлт илгээнэ. Ингэснээр өмнөх тестийн санамсаргүй in-memory төлөвт найдахгүй. Бүртгэлийн амжилттай хариунд registrationID-ийн яг утгыг шалгахгүй; зөвхөн тоон төрөлтэй эсэхийг шалгасан. Статус код болон result утгыг тус тусад нь pm.test oracle-оор шалгасан. Нийтийн JSONPlaceholder тест нь 200 статус, массив бүтэц, эхний хэрэглэгчийн нэр гэсэн гурван oracle-той.

## 7. Newman автоматжуулалт ба үр дүн

Автомат скрипт гурван төлөвийг шалгана:

1. **PASS:** API сервер ассан үед үндсэн collection ажиллуулна. 27 assertion бүгд PASS, Newman exit code 0 байх ёстой.
2. **FAIL:** Тусдаа fail collection дотор зөвхөн эхний амжилттай бүртгэлийн HTTP статусын хүлээлтийг 201-оос 200 болгож зориуд өөрчилсөн. Ингэснээр яг нэг assertion унаж, Newman exit code 1 болох ёстой. Үндсэн collection хэвээр зөв байна.
3. **DOWN:** API серверийг зогсоосны дараа үндсэн collection-ийг ажиллуулна. Гаралт дотор ECONNREFUSED байх ба Newman exit code 1 байна. Энэ нь oracle-ийн логик алдаа биш, сервертэй холбогдож чадаагүй интерфейс/сүлжээний алдаа юм.

## 8. Дүгнэлт

Энэ лабораторид Лекц 5-ын тест дизайны таван алхмыг нэг REST API дээр хэрэгжүүлж, сонголт ба эквивалент ангиас бодит тест кейс гаргах дадлага хийв. Хамгийн их бодол шаардсан хэсэг нь давхар алдааны үед сервер аль алдааг түрүүлж буцаахыг тогтоох байлаа. Идэвхгүй оюутан болон урьдач нөхцөл дутуу байх зэрэг давхар нөхцөлд идэвхгүй шалгалт түрүүлж байгааг тусдаа кейсээр шалгасан. Мөн оюутан болон хичээл хоёулаа байхгүй үед ERROR_NO_STUDENT түрүүлж буцаж байгааг шалгав. Урьдач нөхцөлийн бүгдийг хангасан, огт хангаагүй, заримыг хангасан гурван хувилбарыг ялгаж тестэлсэн. Тест бүрт өөрийн setup хүсэлт байрлуулснаар in-memory серверийн өмнөх төлөвөөс хамаарах эрсдэлийг бууруулсан. Newman-аар үндсэн collection, нэг oracle зориуд буруу болгосон fail collection, сервер унтраасан down төлөвийг тус тус шалгаж болно. Зориудын FAIL нь тестийн хэрэгсэл буруу хүлээлтийг илрүүлж чаддагийг, DOWN нь oracle-ийн алдаанаас тусдаа холболтын алдааг харуулдаг. Өгөгдсөн API-ийн хариунууд зааврын статус болон result семантиктай таарч байгаа эсэхийг бодит Newman log-оор нотолж тайлагнана.

## 9. Ажиллуулах команд

Node.js болон Newman суулгасны дараа төслийн үндсэн хавтаснаас:

    node server.js

Өөр терминалаас бүх нотолгоог үүсгэх:

    bash scripts/verify-lab.sh

Зөвхөн үндсэн collection-ийг гараар ажиллуулах:

    newman run lab05-collection.json
